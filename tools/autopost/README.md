# Глашатай — автопостинг «Осколков хаоса»

Сервис публикует посты группы во ВКонтакте, на YouTube, в Instagram и TikTok по расписанию. Из одного кабинета видно очередь, ошибки, ссылки на вышедшие посты и цифры просмотров.

Сейчас это **локальный тестовый образец**:
- работает на ноутбуке;
- по умолчанию включён тестовый режим: очередь, проверки и статусы настоящие, но на площадки ничего не уходит.

## Запуск

```sh
cd tools/autopost
cp .env.example .env      # AUTOPOST_DRY=1 — тестовый режим
npm start                 # → http://localhost:4777
npm run demo              # пробный план недели релиза «Ворожеи» (черновиками)
npm run demo -- --fast    # тот же план, сжатый в минуты и сразу в очереди — смотреть, как работает
npm test
```

Нужны Node 24+ и ffmpeg (ffprobe), которые уже стоят. Зависимостей из npm нет.

**Вход.** В кабинете два пользователя с одинаковыми правами: Владислав и Ярослав. В журнале видно, кто что сделал. Завести человека или выдать новый пароль:

```sh
npm run user -- yaroslav "Ярослав"     # печатает логин и пароль
```

Пароль меняется в кабинете: меню с именем → «Сменить пароль».

**Ключи площадок вставляются в кабинете**, файлы править не нужно. В «Площадках» у каждой площадки есть «Настройка»: пошаговая инструкция, адрес входа с кнопкой «Копировать» и поля для ключей. Ключи хранятся в базе зашифрованными и после сохранения не показываются. Там же, в карточке «Сервис», включается и выключается тестовый режим, настраиваются уведомления в Telegram (с кнопкой проверки) и публичная папка.

## Как устроено

```
пост (ролик / картинка / карусель / текст + общая подпись)
 └─ публикации: VK·клип 12:00 · YouTube·Shorts 12:00 · Instagram·Reels 12:00 · TikTok·черновик 12:00
      у каждой своё время, своя подпись (по желанию) и свой статус
```

**Статусы публикации:**

| Статус | Что значит | Что делать |
|---|---|---|
| Черновик | собрано, но не одобрено | «В очередь» — сервис проверит файлы и подключение |
| В очереди | выйдет в своё время | — |
| Публикуется | идёт загрузка | — |
| Опубликовано | вышло, есть ссылка; раз в 6 часов собираются цифры | — |
| Ошибка | площадка отказала, на ней ничего не появилось | исправить и снова в очередь |
| Проверить вручную | связь оборвалась посреди отправки — неизвестно, вышел ли пост | посмотреть площадку: «Вышло — вставить ссылку» или «Не вышло — в черновик» |
| Выложить вручную | формат площадки нельзя опубликовать по API, или выбрано «вручную» | «Пакет»: подпись копируется кнопкой, файлы скачиваются; после публикации вставить ссылку |

**Правила публикации** взяты из Нейро-продюсера. Главный принцип: не опубликовать — не страшно, опубликовать не то или дважды — плохо.
- Попытка отмечается **до** отправки.
- Повтор идёт сам (с паузой 1, 4 и 16 минут) только если площадка точно ничего не получила.
- При опоздании больше чем на 6 часов (например, ноутбук был закрыт) пост не публикуется: «завтра релиз», вышедшее после релиза, хуже, чем ничего.
- Если процесс упал посреди отправки, после перезапуска публикация получает статус «проверить вручную», а не отправляется повторно.
- Перед постановкой в очередь каждый файл проверяется под правила площадки: длина и вертикальность ролика, размер, JPEG для Instagram, длина подписи.

**Файлы:**

| Файл | Что в нём |
|---|---|
| `server.js` | кабинет и API; расписание: публикации раз в 20 с, цифры и продление ключей раз в час |
| `publish.js` | очередь и правила публикации |
| `db.js` | SQLite (`data/autopost.db`) |
| `secrets.js` | ключи площадок, зашифрованы AES-256-GCM |
| `media.js` | проверка файлов (ffprobe) |
| `pubmedia.js` | публичная ссылка на файл для Instagram |
| `platforms/*.js` | по файлу на площадку |
| `docs/площадки.md` | что каждая площадка разрешает по API, с источниками |

## Подключение площадок

Пока не подключено ничего: ключей нет, и сервис работает в тестовом режиме. Ниже — что сделать для каждой площадки. Подробности и ограничения — в [docs/площадки.md](docs/площадки.md).

### ВКонтакте (5 минут)
1. В сообществе открыть «Управление → Работа с API → Ключи доступа → Создать ключ». Права: «управление сообществом», «фотографии», «истории».
2. Вставить ключ и id сообщества в кабинете: «Площадки → ВКонтакте».
3. Опубликовать первый пост и проверить, что он вышел. Ключ сообщества для постов VK официально не описывает (подробности в [docs/площадки.md](docs/площадки.md#вконтакте)).

**Автоматом** публикуются посты с картинками и истории. **Вручную по «Пакету»** — клипы, видео и релизный пост с треком: у VK нет для них открытого API. Сервис напомнит в срок, в том числе в Telegram, и даст подпись и файл.

### YouTube (≈15 минут, один раз)
1. В [console.cloud.google.com](https://console.cloud.google.com) создать проект и включить **YouTube Data API v3**.
2. Открыть **OAuth consent screen**:
   - тип External;
   - добавить себя;
   - нажать **Publish app**, чтобы статус стал «In production». Проверять приложение не нужно; без публикации вход слетает каждые 7 дней.
3. **Credentials → Create OAuth client → Desktop app**. Скопировать Client ID и Client secret в кабинете: «Площадки → YouTube → Настройка». На сервере тип клиента — Web application с адресом из кабинета.
4. В кабинете: «Площадки → YouTube → Войти». Google предупредит о непроверенном приложении: «Дополнительно → Перейти».

### Instagram (≈20 минут; нужен прокси)
1. Аккаунт группы перевести в **профессиональный** (Автор или Бизнес).
2. На [developers.facebook.com](https://developers.facebook.com) создать приложение типа **Business** и добавить продукт **Instagram**.
3. Открыть «API setup with Instagram login», добавить аккаунт и нажать **Generate token**. Ключ вставить в кабинете: «Площадки → Instagram». Дальше сервис продлевает его сам.
4. Прокси (`NODE_USE_ENV_PROXY=1`, `HTTPS_PROXY=…`) задаётся в настройках сервера, а не в кабинете: из РФ Instagram API закрыт.
5. Настроить публичную папку для файлов (`MEDIA_SCP_TARGET`, `MEDIA_PUBLIC_URL`): Meta забирает ролики только по ссылке. На сервере это отдельная папка и одна строка в nginx (`location /m/`). **Это ещё не сделано: сервер пока не трогали.**

### TikTok (сначала проверка аккаунта)
1. Проверить, что аккаунт **может загружать видео**. Аккаунтам из российского региона TikTok загрузку закрыл; нужен аккаунт, заведённый вне РФ.
2. На [developers.tiktok.com](https://developers.tiktok.com):
   - создать приложение, платформа **Desktop**;
   - Redirect URI: `http://localhost:4777/oauth/tiktok/callback`;
   - продукты **Login Kit** и **Content Posting API**.
3. Скопировать Client key и Client secret в кабинете («Площадки → TikTok → Настройка») и нажать «Войти».
4. Формат по умолчанию — **черновик**: ролик приходит во «Входящие» TikTok, вы вставляете подпись и жмёте «Опубликовать». Открытая публикация по API требует аудита TikTok, а «инструменты для своего аккаунта» он не пропускает.

## На сервере (чтобы зайти мог и Ярослав)

Адрес: **https://glashatai.oskolkihaosa.ru**. Сервер тот же, что у сайта.
1. У регистратора домена добавить DNS-запись: `A  glashatai  <IP сервера>`.
2. Выполнить `sh tools/autopost/deploy/deploy.sh --install` из корня репозитория. Скрипт заведёт:
   - пользователя `glashatai`;
   - свой Node 24 в `/opt/glashatai/node` (системный Node 22 соседей не трогается);
   - службу `glashatai` на порту 3400;
   - файл nginx и https.

   Перед перезагрузкой nginx скрипт проверяет конфигурацию (`nginx -t`).
3. Завести пользователей командой из вывода скрипта.
4. Дальше обновления выкладываются `sh tools/autopost/deploy/deploy.sh`.

Площадки подключаются уже в серверном кабинете: адреса входа там другие (`https://glashatai…/oauth/…/callback`).
- **Google:** клиент типа **Web application**.
- **TikTok:** платформа **Web**.

Рубрика «Пророчество дня» рисует картинки через Chrome, а на сервере его нет. Её пока запускать с ноутбука.
