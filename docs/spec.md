# Как устроены «Осколки хаоса» — технический документ

Опора для кода: читать перед работой с сайтом или Глашатаем. Решение поменялось — поправить здесь.
Цель и принципы — [principles.md](principles.md). Адреса и доступы сервера — только в `CLAUDE.local.md` (репозиторий публичный).

## Обзор

Две части. **Сайт-кодекс** oskolkihaosa.ru — лор, песни, «слушать», гадание Ворожеи; статика без сервера.
**Глашатай** — наш сервис автопостинга для Владислава и Ярослава: контент-план → черновики → утверждение → публикация
по расписанию (или пакет для ручной), напоминания в Telegram, цифры публикаций и сайта.

```
data.js ──► сайт (index.html + app.js) ──► nginx, статика
   │
   └──► Глашатай: plans/*.js ──► база (посты, публикации) ──► publish.js ──► platforms/* ──► YouTube, Instagram, Telegram
                                     │                         │                 └─ VK, TikTok: пакет в бот, человек выкладывает сам
                                     │                         └─ notify.js ──► бот Telegram (пакеты, «✓ Выложил», тревоги)
                                     └─ кабинет web/ (вход по паролю) · analytics.js (цифры, Метрика) · oracle.js (Ворожея в комментариях)
```

## Стек

| Слой | Технология | Почему |
|---|---|---|
| Сайт | HTML + CSS + обычный JS, без сборки | статика, грузится быстро, правится без инструментов |
| Контент сайта | `data.js` — один файл | лор, песни, пророчества в одном месте; его же читает Глашатай |
| Глашатай, сервер | Node 24, ESM, `node:http` без фреймворка | ноль зависимостей из npm — нечему ломаться и устаревать |
| База | SQLite (`node:sqlite`), файл в папке данных | один процесс, мало данных, без отдельной службы |
| Кабинет | `tools/autopost/web/` — обычный JS-модуль, без сборки | два пользователя, простые экраны |
| Видео | ffmpeg / ffprobe | проверка файлов под площадки, обложки, ролики |
| Проверки | ESLint, `node:test`, puppeteer-core + Chrome | `npm run check` из корня |

## Архитектура — правила зависимостей

- **Статусы публикаций меняет только `publish.js`** (и кнопки кабинета через `server.js`). Площадки статусы не трогают:
  они публикуют и возвращают результат или бросают `notSent` (точно не ушло) — от этого зависит, будет ли повтор.
- **`platforms/*.js` — по файлу на площадку**, общий вид: `publish`, `stats`, `followers`, `formats`. Друг друга не импортируют;
  общее — в `platforms/http.js`. Из верхних модулей берут только `db`, `secrets`, `media` и `notSent`.
- **Ключи площадок — только через `secrets.js`** (зашифрованы в базе). В код, журнал и ответы API не попадают.
- **Сообщения в Telegram — только через `notify.js`.**
- Кабинет (`web/`) ходит в базу только через API `server.js`.
- Главный принцип публикации: не опубликовать — не страшно, опубликовать не то или дважды — плохо.
  Попытка отмечается до отправки; повтор — только если площадка точно ничего не получила; упал посреди отправки →
  «проверить вручную», а не повтор.

## Площадки в Глашатае

| Площадка | Как выходит | Цифры |
|---|---|---|
| YouTube Shorts | сам | просмотры, лайки, комментарии |
| Instagram Reels | сам (файл Meta забирает по публичной ссылке) | с правом `instagram_manage_insights` |
| Telegram | сам, с кнопками «слушать» | — |
| VK | вручную: пакет в бот → человек выкладывает → «✓ Выложил» | Глашатай сам находит пост или клип на стене |
| TikTok | вручную, так же | с правом `video.list`, ролик находит по времени |

- Telegram, Instagram, TikTok и YouTube из России — через прокси; VK и Яндекс — напрямую.
- Instagram иногда блокирует доступ («API access blocked»): Владислав подтверждает аккаунт в Meta.
  Надёжное решение на будущее — системный ключ в Meta Business.
- Повторный вход в YouTube и TikTok с сервера упирается в адрес возврата приложений — входить локально и переносить ключ.

## Данные (база Глашатая)

| Таблица | Что | Кто меняет |
|---|---|---|
| `posts` | пост: название, вид, подпись, файлы, релиз, комментарий, утверждение | plan.js, кабинет |
| `targets` | публикация поста на площадке: время, режим (auto / manual), статус, ссылка, цифры, сообщения бота | publish.js, кабинет, бот |
| `accounts` | подключение площадок, ключи (зашифрованы) | secrets.js |
| `users`, `sessions` | Владислав и Ярослав, входы | auth.js |
| `settings` | настройки сервиса из кабинета | кабинет |
| `events` | журнал: что, кто, когда | все через `log()` |

Статусы публикации: черновик → в очереди → публикуется → опубликовано / ошибка / проверить вручную / выложить вручную.

## Безопасность

- Вход в кабинет по паролю (два пользователя, права одинаковые); сессии в базе.
- Ключи площадок вставляются в кабинете, хранятся зашифрованными (AES-256-GCM); ключ шифрования — в настройках сервера.
- Настройки сервера — файл окружения на сервере (пример — `tools/autopost/deploy/glashatai.env.example`), не в git.
- Глашатай на общем сервере ограничен по памяти и процессору и останавливается первым — соседи важнее.

- `tools/autopost/test.js` — правила публикации на временной базе: повторы, «проверить вручную», проверка файлов,
  ручные пакеты и «✓ Выложил», Ворожея. Площадки подменены, в сеть не ходим.
- `tests/site.test.js` — Chrome проходит главный путь посетителя сайта: печать → герои и песни → карта Ворожеи →
  кнопки «слушать». Внешние запросы отрезаны. Нет Chrome — тест пропускается.
